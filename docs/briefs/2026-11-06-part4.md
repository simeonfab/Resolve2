## 1. Fixes to Part 3 (do these first)

1. Home layout is broken. The cards run off the right edge of the window, and Recent pages and Projects overlap Next 7 days. Nothing on any screen may overflow sideways or overlap, at any window width from 1280 px up. Wrap long text. Prove it with screenshots at 1280 px and 1920 px.
2. First run in the main window. A new user must land straight in the intake inside the main Resolve window. Not a second window. Prove it: create a brand-new workspace and screenshot each step from launch to "Open my project". Test Intake keeps its own window and sandbox, as you built it.
3. Confirm understanding. Remove the "Yes, this is the outcome, in my words" tick. Give two actions only: "This looks right, show me the proposal" and "Something's wrong, let me change it". The second puts the cards straight into edit mode. Editing the outcome card counts as confirming it in the user's words.
4. Text on the confirm cards:
   - Start every sentence with a capital letter.
   - Write in second person or project terms. "Where it is" currently reads "the user has sketched some screens but hasn". Never "the user", which is the known failure again.
   - Never cut text off mid-word. Cards grow to fit.
5. Present the ending like original Resolve. The proposal screen does the right thing but is hard to read. Keep the proposal data and editing, and change the presentation to the original Resolve ending (pictures 05 to 09 in docs/reference/original-resolve):
   1. Next move: one clear recommended first move, with why.
   2. Roadmap themes, confirmed one card at a time: "Yes, add to my roadmap" or "Not quite".
   3. First week: "Here's where to begin", the first tasks in order.
   4. Whole picture: Now, Next and Later, then Adopt.
   - A "See and edit everything" link opens the full proposal editor you built, for H0, Hx/NHx, E0, uncertainties and knowledge pages.
6. Speed. A full Claude Code run took about 5 minutes, which is too slow. No single screen should wait more than about 5 seconds without visible progress, and no wait should pass 15 seconds:
   - Precompute in the background while the user reads or types (the next question, classification, the understanding).
   - Show what is happening during any wait.
   - Prefer the Anthropic API path when a key exists. It avoids starting the CLI on every call.
   - Report the time taken per step from a real run.
7. Ollama default. Recommend qwen3 (named in the tutorial) over llama3.2 for intake. When llama3.2 is selected, show a one-line note: "Fine for trying the flow, weak for real projects".
