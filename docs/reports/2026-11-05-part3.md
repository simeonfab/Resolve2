## What changed (plain English)

1. **The intake is a separate, full-screen front door.** No sidebar or app chrome; only the question, progress, Back/Next, Restart and Exit. A brand-new workspace opens straight into it; **New project** anywhere opens it.
2. **One question at a time, chosen by the AI from your answers, guided by Hypothesis Zero** (`resolveos/h0.md` — the method as you defined it, with an empty "Question set" slot to add yours later without code changes). Coverage targets, not a script; Enter / Shift+Enter / Esc; earlier answers stay editable and later answers built on them get flagged; every question stores why it was asked.
3. **"What Resolve has heard"** sorts each answer into evidence / assumption / open question; you correct it in place, and corrections are never overwritten.
4. **Confirm understanding** (project, goal, state, biggest uncertainty, outcome in your words with a required tick) → **Proposal review** (name + summary, objective and outcome, H0 + Hx/NHx, uncertainties, E0 onward, Now/Next/Later roadmap, tasks, knowledge pages) — every section editable, removable, regenerable; every item tagged evidence / assumption / uncertain → **Adopt** → **Bridge** (real step-by-step writes) → **Roadmap reveal** (once per project, flag stored) → **Open my project** lands on the Overview with Undo.
5. **Adopt writes into the existing stores only**: project + Now/Next/Later sections, Roadmap records, tasks (short titles, detail in notes, basis label, linked to their roadmap item, dates from position), H0/Hx/NHx/E0 records, evidence and untested-assumption records, project brief + other pages, intake transcript with the decision trail, project context.
6. **The five known failures are rules in code**: short real names (never "Resolve is a project to…"), outcome in your words (never a model paraphrase or prompt example), long titles shortened with detail kept, generic filler rejected, assumptions stored as the claim itself. Plus: "evidence" only when it cites heard evidence; heard items must be your own words.
7. **Offline fallback**: no AI → fixed question set over the same targets, proposal built only from your words. If AI stops answering mid-way, the intake switches to the fixed set and says so.
8. **Test Intake** (Home and Settings): its own window and data folder (`%APPDATA%\Resolve2-TestLab`, never served over MCP), TEST MODE banner, five scenarios + own answers, provider per run, inspector (question, H0 reasoning, classification, provider/model, raw request and response), restart / jump / branch, side-by-side compare, save answers + replay, Markdown + JSON export, deliberate "Promote to real project".
9. **Undo + soft deletes everywhere**, **Recently deleted** (Settings → Backups), **backup before every AI write batch**, **Ask AI shows only tool-confirmed results** with a Mismatch warning.
10. **Resolve 2 registered in Claude Desktop** as `resolve2_personal` (Store version's config); `control_centre_personal` untouched.
11. **Inter + DM Serif Display bundled** (OFL; licences in `assets/fonts`).

## What real runs showed (and what was fixed)

- llama3.2 repeats questions, splits answers into fragments, echoes questions into "heard", invents items, copies prompt examples and phrases H0 as a question. Each is now caught: repeats are rejected (fallback to the fixed set), fragments/echoes/invented items are dropped, outcomes and assumptions must be grounded in your words, H0 must be a claim. Its proposals are still thin (e.g. "Develop the app / Test the app"); generic filler triggers one retry, then is kept and labelled by basis. **Use Claude (or another strong model) for real intakes; Ollama is fine for trying the flow.**
- Claude Code: good questions and proposal, but slow (≈5 minutes for a full run, each call starts the CLI).

## Test it yourself

1. Open Resolve 2 (desktop icon or `app\Open Resolve 2.cmd`).
2. **Test Intake**: Home → **Test Intake** (or Settings → General → Open Test Intake). A second window opens with a yellow TEST MODE banner.
3. Choose **AI for this run**: "Ollama (local)" (model `llama3.2`) or "Claude Code". Click **Doom Clock corporate events** (or any scenario, or **Use my own answers**).
4. The opening text is filled in — press **Continue**. For each question, click **Inspector** (top right) and **Answer from scenario**, or type your own; watch **What Resolve has heard** fill in. Try **Back**, the question numbers, changing an earlier answer (later ones get a "does this still hold?" flag), and **Branch from here**.
5. Press **Show me the proposal**, fix the cards, tick **"Yes — this is the outcome, in my words"**, continue. Edit, remove and **Regenerate** parts of the proposal; click a label to change evidence/assumption/uncertain.
6. **Adopt**, watch the bridge, then the roadmap reveal → **Open my project**.
7. Back in the lab (Exit), tick two runs → **Compare proposals**; try **Export Markdown + JSON** and **Save answers for replay**; **Promote to real project…** → **Yes, promote** to create it in your real Resolve 2.
8. Without the lab: in the main window, **New project** runs the same journey for real. **Esc** leaves and saves; it resumes where you stopped.
9. Undo: complete or delete a task → **Undo** in the toast; Settings → Backups → **Recently deleted** → Restore.
10. Claude Desktop: fully quit Claude (tray icon → Quit), reopen, enable **resolve2_personal** in the tools menu, ask "what Resolve projects do I have?".
11. Headless check (optional): `target\debug\resolve2.exe --testlab --lab-run "Service business" --provider ollama --model llama3.2 --url http://localhost:11434`.
