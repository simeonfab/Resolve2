## What changed, in plain English

1. **One download.**
   - The zip holds just the program and a README with three steps to start. The README covers the SmartScreen warning ("More info", then "Run anyway").
   - The release build opens as a normal window (no black console window behind it). Helper programs it starts, such as Claude Code, run hidden too.
   - A fresh copy starts empty: one blank "Personal" workspace, no demo workspace, no keys. The first launch opens "Connect your AI", then the intake.
   - The version, "Alpha 0.1, 6 Nov 2026", shows in Help and at the top of Settings.
2. **Connect your AI** (`01-first-launch-connect-your-ai.png`, `07-settings-ai.png`) is the first screen, and also the top of Settings → AI. It offers three big choices, in order:
   - **Claude Code** (recommended): it detects whether Claude Code is installed and signed in. If not, it shows the two setup steps and "Check again".
   - **Ollama**: it detects Ollama and its models, and offers "Download qwen3" with progress. If only llama3.2 is there, it says "Fine for trying the flow, weak for real projects".
   - **Claude API key**: paste the key, then Test.

   Every Test makes a real AI call and shows ✓ with the AI's actual reply, or a plain error. **Continue** only unlocks after a passing test. "Skip for now" uses the fixed question set.
3. **Question cap.**
   - The intake asks at most 8 questions. After the 8th answer it moves on to "Here's what Resolve understood", then the proposal.
   - A question with the same meaning as one already asked is dropped, whether the AI or the fixed set suggested it.
4. **Handoffs are now written for what you type.**
   - The bug: the brief was the same project dump every time, with only one "What to do" line changed.
   - Now the brief is built around your request: what the project already has on that topic, ranked by distinctive words (a word nearly everything mentions, like "café", doesn't count); why it matters; a "Done when" list; and the do-not-do-yet list.
   - With an AI connected, the AI rewrites the brief from your words plus the full project context, in a few seconds. The list shows who wrote each brief.
   - Side by side below.
5. **Import knowledge, sorted automatically** (`02-intake-attach.png`, `03-knowledge-imported-files.png`).
   - **Where to add files:** "📎 Add files" in Knowledge, "📎 Attach a brief or notes" on the intake's first screen, or drag and drop anywhere.
   - **Formats:** .md, .txt, .docx and .pdf.
   - **Sorting:** Resolve files each one under Project brief, Requirements, Research, Documentation, Reference or Evidence & Records, and says where and why. One click on another place moves it. A file filed as evidence also becomes an Evidence record linked to its page.
   - **Without AI:** it sorts by file name and headings and says "a guess".
   - **Intake:** attached files feed the questions, the understanding and the proposal like typed text. The AI is told that a claim from a file is evidence only where the file states it as fact; everything else is an assumption. On Adopt, the files are filed in the project's Knowledge.
6. **Help is a guide** (`04`, `05`, `06`): sections down the left.
   - The sections: Welcome (your message and Report a problem), Quick start (five steps), Requirements, one section per part of the app (Roadmap explains milestones, dependencies, gates and "Coming up"), Tips (Windows+H for voice typing), and Troubleshooting (AI not connecting, SmartScreen, where data lives).
   - The old tutorial is kept and filed under these sections. Its out-of-date parts (the old sidebar, the Sample workspace, developer paths) were updated.
   - "Copy as text" copies the whole guide.
7. **Settings in four tabs** (`07`–`10`):
   - **AI:** Connect your AI, other AI options, and usage & cost.
   - **General:** appearance, workspace name and colour, Test Intake, keyboard shortcuts.
   - **Your data:** recently deleted, backups, import and export.
   - **Advanced:** phone and sync, the hub, sync folder, AI apps over MCP (Claude Desktop, Claude Code, Codex, ChatGPT), calendar subscriptions, where your files are, opening Resolve, all workspaces.
   - Cards have a title, one sentence, then the controls, with longer text behind "Learn more". The first three tabs show no file paths or tokens.
8. **AI Team cards** (`11-ai-team-cards.png`): five equal cards on one row. The selected card gets a highlight border only, and nothing moves.
9. **Report a problem** (Help → Welcome, and Settings → AI) copies four things: the version, the Windows version, the AI in use and the last error message. It includes no personal data or project content, and says "Paste this to Simeon".

## Deviations and things to know

1. **I couldn't use a separate Windows account or a virtual machine.**
   - **What I did instead:** see "Clean-account test" above.
   - **Proven:** the exe needs only DLLs that ship with Windows (no Rust, MinGW or Visual C++ runtime); it starts and draws from a freshly unzipped folder; it uses an empty user profile and data folder and builds a fresh, key-free one; nothing found Rust, Git, Node, Claude Code or Python on its PATH.
   - **Not proven:** a different Windows install, different graphics drivers, Windows 10. Making a new Windows account needs administrator rights and changes the PC, so I didn't. Windows Sandbox isn't available on Windows Home.
   - **One real risk:** Resolve draws with OpenGL. A PC or virtual machine without a proper graphics driver may not open the window. The README says to update the graphics driver and tell you.
2. **The cap moves on to the confirm screen, not straight to the proposal.** After 8 questions you land on "Here's what Resolve understood" (one click on "This looks right" shows the proposal). This keeps the confirm step from the Part 3 brief. Say if you want it to skip confirm.
3. **PDF reading is basic.** Ordinary PDFs saved from Word, Google Docs and similar work. Scanned PDFs, or PDFs with unusual font encodings, are refused with a plain message ("copy its text into a .txt or .docx") rather than imported as nonsense. I tested a generated PDF, not real ones from your Documents folder (those are personal).
4. **Claude Code sign-in detection** checks that Claude Code's sign-in file exists (it never reads it). The Test button is what proves sign-in.
5. **The release exe names you in two places, neither secret.** The build paths are remapped, so `C:\Users\simeo` is no longer inside it. What remains:
   - "simeonfab/ResolveOS": the source line in the bundled ResolveOS role prompts (your GitHub handle).
   - "Paste this to Simeon" and the Welcome text, as the brief asked.
6. **The fixed question set** (no AI) used to ask 9 questions; with the cap it asks 8, so one target ("constraints") goes unasked without AI.
7. **Knowledge categories map onto existing places.**
   - Brief, requirements, research, documentation and reference files are pages tagged with their place, hanging under the project brief.
   - Evidence files are a page plus a linked Evidence record.
   - No new store was added.

## Test steps for testers (and you)

1. Unzip `Resolve2-alpha-2026-11-06.zip`, then double-click `resolve2.exe`. On the SmartScreen warning, click More info, then Run anyway.
2. Connect your AI: press Test on one choice and wait for the green tick, then Continue. Or try "Skip for now".
3. On "Tell Resolve what's going on", type a few lines and optionally attach a .docx or .pdf brief. Answer up to 8 questions.
4. Check what Resolve understood, go through the proposal steps, then Adopt and Open my project.
5. In Knowledge, press Add files (or drag a file onto the window). Check where it went, and move it with one click.
6. In Handoffs, write two different requests and compare the briefs.
7. In Help → Welcome, press "Copy problem report" and paste it into a message.
